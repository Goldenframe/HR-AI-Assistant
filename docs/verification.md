# Проверка прототипа

Проверка проводится на вымышленных данных. Реальные отзывы, токены и Telegram ID в этот документ не включаются.

Последняя проверка: 13 октября 2026 года. Все 35 программных тестов прошли. Живой импорт загрузил 100 активных аккаунтов Jira, отдельный профиль HR и 64 проекта. Подтверждены 14 аккаунтов Confluence; у остальных используются только данные Jira. Автоматически связаны пространства у 17 проектов; 154 пространства остались без привязки. `--check-team` успешно прочитал 24 записи участия; полнота подбора зависит от прав доступа и подтверждённых связей.

Дополнительная проверка для Nina Kniazeva выявила неполноту глобального поиска пользователей Jira: профиль находился по точному запросу, но отсутствовал в первоначальных 100 результатах. Каталог дополнен 55 профилями по исполнителям, авторам и записям времени в проектах DUNI, MW26, TRCK2. Для Нины найдено 59 других участников; текущая сортировка предлагает первые 20 по числу общих проектов, затем по имени. При отклонении старого логина в JQL участие проверяется по постоянному ключу в заново прочитанных задачах известных проектов. Повторный импорт сохраняет ранее обнаруженные профили после индивидуальной проверки. Первоначальный список из 100 аккаунтов не является полным каталогом компании.

`--check-ai` сформировал отчёты по корпоративной анкете. Последний `--evaluate-ai` прошёл все шесть сценариев. Это проверки конкретных свойств ответа, не доказательство качества всех будущих отчётов. Во время настройки модель возвращала неверные номера подтверждений: передача явных номеров вопросов устранила эту ошибку в проверке. Если модель оставляет выводы по оценкам пустыми, программа показывает подтверждённое согласие/несогласие по конкретным утверждениям и явно помечает его как программный подсчёт. Неверные цитаты и слишком длинные темы по-прежнему отклоняются.

Предыдущий успешный прогон 9 октября относился к анкете из восьми вопросов: Qwen сформировала оба представления отчёта, четыре отдельных набора качества прошли проверки. Эти результаты не подтверждают качество новой анкеты из 50 шагов.

## Программные сценарии

Команда: `python -m unittest discover -s tests -v`.

Проверяются:

1. Автоматический подбор и отметка коллег из общих проектов, снятие выбора, минимум три выбранных профиля, исключение самого сотрудника и HR, запрет добавления людей без общих проектов.
2. Одноразовое подключение профиля и невозможность выбрать роль HR без выданного кода.
3. Ограничение создания опросов о других сотрудниках для обычного профиля.
4. Доступ к ответам только после запуска опроса и только приглашённым коллегам.
5. Выдача отчёта после трёх завершённых отзывов; доступ сотрудника и HR, запрет другим коллегам.
6. Сохранение прогресса после перезапуска и защита от повторной доставки сообщения.
7. Отклонение выдуманной цитаты и противоречия с одним источником.
8. Корректный результат при недостаточных наблюдениях, различия отчётов сотрудника и HR.
9. Полный сценарий кнопок, явное согласие, 43 утверждения и 7 комментариев, завершение только после 50-го ответа. Отдельные кнопки оценок и пропуска комментария; отклонение произвольного текста вместо оценки без потери прогресса.
10. Маркировка демонстрации и актуальность кеша отчёта.
11. Сохранение прежних анкет из трёх и восьми вопросов и продолжение незавершённого опроса после перезапуска; 50 шагов в новых опросах.
12. Проверка цитаты из восьмого ответа, отклонение пропуска как доказательства, нулевая полнота при всех пропусках.
13. Подсчёт распределения оценок, отклонение неполной цитаты оценки и запрет рекомендаций, подтверждённых только оценками.
14. Пагинация Jira/Confluence, запрос исторических назначений и записанного времени, явная связь пространств с проектами, общий проект между разными источниками и сохранение оснований подбора в опросе.
15. Запрет неоднозначных логинов и пространств, сохранение предыдущих данных при ошибке доступа, отказ вместо усечённой выборки. Следующая ссылка Confluence не используется для передачи ключа на другой адрес.
16. Фоновый подбор создаёт черновик для подтверждения, без отправки приглашений; при ошибке не создаёт опрос. Локальная загрузка настроек интеграции сохраняет приоритет переменных окружения.
17. Автоматическая загрузка активных аккаунтов и проектов Jira, подтверждение логина Confluence, пропуск неактивных аккаунтов, отсутствие сопоставления по названиям, сохранение ID при повторном импорте, проверка прав чтения пользователей и отказ при повторении страницы.

Дополнительные проверки покрывают сохранение токена между запусками, приоритет настроек окружения, отклонение некорректного токена, автоматическую доставку приглашений после регистрации, повторные попытки доставки после перезапуска и перевод старых ручных приглашений в автоматическую очередь.

## Корпоративная модель

`python bot.py --check-ai` отправляет три вымышленных отзыва корпоративной Qwen и формирует оба представления отчёта.

`python bot.py --evaluate-ai` оценивает шесть отдельных наборов:

| Набор | Проверяемый результат |
|---|---|
| Только критические отзывы | Модель не придумывает сильные стороны и сохраняет зоны развития |
| Противоположные наблюдения | Модель выделяет разные мнения, подтверждённые минимум двумя отзывами |
| Общие ответы без примеров | Модель не формирует неподтверждённые выводы и рекомендации |
| Все вопросы пропущены | Модель не делает выводов; полнота по всем разделам равна нулю |
| Только отрицательные оценки | Модель выделяет зоны развития и не добавляет похвалу |
| Противоположные оценки | Модель выделяет разные мнения по одним и тем же утверждениям |

Программа проверяет структуру и ссылки на оригинальные цитаты. Оценка смысла человеком остаётся необходимой. Время отдельных запросов зависит от загрузки сервиса и не является гарантией производительности.

## Проверка в Telegram

Запуск с новым токеном BotFather и прохождение сценария в живом Telegram должны выполнить участники команды. При разработке используются имитации Telegram-запросов: сообщения реальным людям не отправляются.


Отчёт v5: объяснения подтверждённых наблюдений, предложенные ИИ действия и способ проверить результат. Таблицы оценок и квадратные скобки не показываются сотруднику. Исходные ответы открываются отдельно, включая тест из двух ролей. Проверяется направление оценок и противоположность оценок одного критерия; несогласованность оценки с комментарием одного автора выделяется отдельно. Неподтверждённый пункт удаляется, другие подтверждённые пункты сохраняются. Эти проверки подтверждают ссылки на ответы и направление шкалы, но не заменяют содержательную проверку интерпретации. Старые кеши не используются для нового формата.


Рекомендации отчёта — необязательные варианты развития без срока «две недели». ИИ предлагает небольшие изменения в текущей работе, не назначает дополнительную нагрузку и не делает выводов о занятости без данных. Месяц или квартал предлагаются как горизонт обсуждения с руководителем. Перед формированием настоящего отчёта бот получает доступные незавершённые задачи, назначенные сотруднику в Jira: количество, ближайшие и прошедшие сроки, оставшееся оценённое время и число задач без оценок. Сводка передаётся ИИ отдельно от отзывов. Календарь, отпуска и полная рабочая ёмкость неизвестны; процент занятости не вычисляется. Ошибка Jira не блокирует отчёт. При изменении сводки или даты сохранённый анализ обновляется. Тесты с вымышленным сотрудником не используют нагрузку реального участника.

Исходные ответы выдаются одним XLSX: вопросы по столбцам, отзывы по строкам, авторы обозначены номерами. Проверяется точное сохранение текста, отсутствие формул из пользовательского ввода и права доступа. Локальные данные и готовые выгрузки исключены из Git.
